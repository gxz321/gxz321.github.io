01 / THE QUESTION

What does it take to connect a policy to a robot?

A robot-learning tutorial spans several systems: demonstrations, model training, inference services and a simulated robot. This project starts from donghoYee's Isaac Sim with GR00T Tutorial and examines the interfaces that connect those systems.

The upstream tutorial targets GR00T N1.5. The immediate objective is a clearer engineering workflow with explicit configurations and checks, establishing the groundwork for later experiments with compatible software, data and scene assets.

02 / THE METHOD

Define the contract from observation to action

Training requires a LeRobot-compatible dataset and a matching robot configuration. At runtime, camera images, robot state and a task instruction must reach the policy service; its returned actions must then map correctly to the simulated robot's joints.

The engineering work separates these concerns through configuration management, preflight checks and an explicit observation-action protocol. This makes each connection possible to inspect before attempting a full simulation run.

SYSTEM MAP

Three interfaces.

01DatasetDemonstrations required

Preflight checks inspect the expected dataset structure. Real SO-101 demonstrations, synchronized cameras, and verified joint units still need to be provided.

02PolicyProtocol tested

The dual-camera HTTP interface, explicit mock and real backends, and joint mapping are implemented. Seven CPU tests pass. Actual learned-policy inference requires a compatible checkpoint and environment.

03SimulationGPU evaluation pending

The bounded rollout entry point is written. A calibrated scene, verified assets, real model outputs, and GPU task evaluation remain necessary before reporting robot capability.

03 / WHAT EXISTS

An interface that can be checked in stages

The current package provides a shared HTTP interface for two camera observations, real-policy and mock backends, joint mapping and dataset preflight checks. A mock backend supports protocol debugging before model inference and simulation integration are available.

Seven CPU protocol tests pass. The downloadable engineering package contains the configuration and implementation; real-model inference, GPU training and closed-loop task performance in Isaac Sim remain unverified.

04 / WHAT COMES NEXT

Does the complete loop work?

The next stage is to fix software and model versions, prepare matching demonstrations and scene assets, and run the complete observation-policy-action loop. Training configuration, inference latency, task outcomes and failure cases should be recorded together.

These experiments are still pending. The current engineering checks demonstrate protocol behavior, rather than a robot task success rate or validated autonomous manipulation.
